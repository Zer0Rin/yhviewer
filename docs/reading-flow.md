# 连续滚动与大 TXT（v0.8）

## 大 TXT 秒开

v0.7 每次打开 TXT 都把整本书解码进内存、对全文跑多行正则切章、再把每章复制一份。几千万字的小说在手机上要十几秒，内存里同时有三四份全文。

v0.8 改成"切一次，记下来"：

- 导入时切章（`TxtChapters.ranges`，逐行扫描，只有行首像标题的行才跑正则），把每章正文在 UTF-8 副本里的**字节范围**写进 `files/txt-index/<副本>.idx`（`TxtIndex`）。
- 打开时只读索引（几千行文本）；正文按字节范围从副本里读一章（`TxtBook.text`，带 8 章 LRU 缓存）。
- 索引头记录副本大小和修改时间，对不上就重建；老版本导入的书第一次打开时重建一次。
- 切章结果和 v0.7 逐字一致（`TxtIndexTest.splitMatchesV10Exactly` 用旧实现随机对照 300 份文档），已保存的章节号不会错位。

2280 万字、4000 章的合成小说，JVM 解释执行（接近手机冷启动）：旧的打开约 22 秒，新的读索引约 0.07 秒；切章只在导入时做一次。

## 章节连续滚动

```
WebView（只有一个滚动条）
└─ /flow/index.html      外层页面：只有我们自己的脚本（FlowShell）
   ├─ <iframe sandbox="allow-same-origin" src="/book/…/c5.xhtml">   EPUB 章节
   ├─ <iframe …  src="/txt/6.html">                                TXT 章节（TxtChapterPage 按需渲染）
   └─ …最多 5 章
```

- **安全边界不变**：书的内容在 sandbox iframe 里，没有 `allow-scripts`，脚本、事件处理器一律不执行；章节响应仍带 `script-src 'none'`。外层页面开 JS 只是为了运行我们自己的布局脚本。
- **窗口化加载**：离底部不到两屏补下一章，离顶部不到一屏补上一章，一次只加载一章；超过 5 章从远的一头移除。
- **滚动锚定**：在视口上方插入、移除章节，或上方章节的图片加载完变高时，按"视口顶部所在章节 + 偏移"补偿滚动位置，正在读的文字不跳。
- **高度**：iframe 高度 = 章节内容高度。字号变小时章节会变短，所以重新排版时先把 iframe 压到 0 再量，同时用 `min-height` 撑住页面防止滚动位置被截断。
- **实时排版**：主题、字号、行距由外层页面直接改各章 iframe 里的 `data-theme` 和 `<style id="yh-reading">`，不重新加载，位置按"章节 + 章内比例"恢复。
- **没有 JS 桥**：原生端在滚动后用 `evaluateJavascript` 读 `YH.state()`（"当前章,章内比例"），更新顶栏标题、目录高亮并保存进度；查找栏打开时 `YH.hold(true)` 暂停补章。
- **章节内链接**：点链接时 iframe 的导航被 `shouldOverrideUrlLoading` 拦下，交给阅读器跳章（带锚点）。

Aa 面板里可以关掉"章节连续滚动"，回到一章一页。
